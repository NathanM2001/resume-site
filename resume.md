## Projects

### AI Resume Assistant (In Progress)
This website is Nathan's first agentic AI project. It is an interactive resume with an AI chat assistant that visitors can ask about his background, skills, and projects. He started building it in November 2026 to gain hands-on experience with the software development lifecycle, infrastructure, prompt engineering, and agentic AI.

#### How it works
When a visitor asks a question, the website sends it to a small server function. The server function adds Nathan's resume file and a set of rules (the system prompt), then sends everything to the Claude API. Claude writes the answer, and the server sends back only the answer text. The API key is stored securely on the server and is never visible to visitors.

The assistant answers only from the information in Nathan's resume file. If a question isn't covered, it says it doesn't have that information instead of guessing. This approach is called grounding, and it prevents the AI from making things up.

#### How Nathan is building it
Nathan uses Claude Code, an AI coding agent, as his developer while he acts as the product owner and reviewer. He writes the requirements, asks Claude Code to plan before building, reviews every change before accepting it, and tests the results himself. He types all Git commands himself and writes the key pieces of the project on his own, including the system prompt, the test questions, and the README. He also gave Claude Code a set of standing rules in a CLAUDE.md file, such as explaining every change, planning before larger changes, and never putting secrets in code.

#### Nathan's technical role
Using an AI coding agent doesn't mean skipping the technical work. Nathan understands how the project fits together and makes the technical decisions:
- **Architecture:** he designed how the site works, with the browser sending questions to a server function, the server function calling the Claude API, and the API key kept on the server so visitors can never see it.
- **Code review:** he reviews every change Claude Code proposes before accepting it, and asks for a plain-English explanation of any line he doesn't understand.
- **Version control:** he runs all Git commands himself (init, add, commit, push, branches) and writes his own commit messages.
- **Testing:** he wrote the test questions and expected answers used to check that the AI responds correctly.
- **Background:** he took coding and software development courses in college as part of his Management Information Systems degree, and built automated Salesforce Flows during his internship.

Nathan sees AI coding agents the way many engineering teams now do: they speed up the writing of code, while a person stays responsible for the design, the review, the testing, and what gets shipped.

#### Tools and technology
- **Editor:** VS Code
- **AI developer:** Claude Code
- **Version control:** Git and GitHub
- **Website:** HTML, CSS, and JavaScript
- **Hosting:** Vercel (planned), which redeploys the site automatically each time new code is pushed to GitHub
- **AI model:** Claude, through the Claude API (planned)

#### Design decisions
- **One source of truth:** the resume file feeds both the website and the AI assistant, so information only needs to be updated in one place.
- **Secrets stay on the server:** the API key is stored in an environment variable, never in the code or on GitHub. A .gitignore file was set up before any code was written so secret files can't be saved by accident.
- **Plain JavaScript:** it runs in the browser and on Vercel with no extra build step, which keeps the project simple. On a larger team, TypeScript would be worth considering.
- **A fast, low-cost model:** a smaller Claude model is enough to answer questions from one resume and keeps costs and response times down.
- **Privacy:** the site leaves out Nathan's phone number and any internal details from his employer, because the website and code are public.

#### Testing
Before writing the content, Nathan wrote 23 test questions the assistant must handle, each with an expected answer. They cover recruiter questions, AI hiring manager questions, behavioral questions, and edge cases such as salary questions (which should be redirected), facts not in the resume (which should not be made up), off-topic requests, and attempts to override the assistant's rules. Some questions ask the same thing in different words to check that the assistant finds the right answer however it's phrased. This approach of writing tests first is called eval-driven development.

## Stories

### Getting a store open on time when install week fell apart
**Situation:** Nathan and a coworker traveled to a new store for install week, which ran from a Monday in early July through that Friday. The team had started traveling to install weeks to get better control of the process and to catch issues directly, because store staff aren't in IT and don't always report problems clearly. At the time, the team sent the Bill of Materials to its equipment vendor two weeks before install week: one week for the vendor to palletize the equipment and one week for freight. Nathan had sent the BOM on time, but the vendor gave little to no update on the pallets' status before the trip.

**Task:** Install week has a hard deadline. All equipment must be installed by Friday, because the following week the store begins merchandising and needs to print labels and look up pricing. The grand opening date could not move.

**Action:**
- **Monday:** Neither of the vendor's two technicians showed up. Two data runs were missing, none of the cabling had been terminated, and none of the equipment pallets had arrived, including all of the network and store systems equipment.
- **Tuesday:** The technicians still didn't show up, but the vendor arranged for technicians already on site doing other work to help. Two pallets from a second vendor arrived, along with the data cabinet, but most of the critical equipment was still missing. The team set up the self-checkout kiosks, which couldn't go further without data connections.
- **Wednesday:** Technicians came briefly but left for another job because the main pallets still hadn't arrived. Nathan and his coworker used the time to agree with the technicians on what to install first, and they staged all of the equipment on hand so installation would go faster once the rest arrived.
- **Thursday:** The pallets still hadn't arrived, and work was at a standstill.
- **Friday:** The remaining pallets arrived at about 1:40 PM, the day Nathan and his coworker were scheduled to leave. Instead of leaving around 6 PM as planned, they stayed late to install the most critical equipment, even with a five-hour drive home ahead of them. They installed both front registers, including the main register that controls the store, along with PIN pads, cashier and customer displays, receipt printers, and scanners, and had the data drops terminated for them. They also set up the framing counter computer and monitor.
- **The following Monday:** The team brought in technicians from a different company. They had the technicians bring the network online first, then got the most important systems online and configured so the store could print labels and use handheld devices to start merchandising. After that, they worked through the remaining, less critical equipment.

**Result:** The store opened on time. By prioritizing the systems the store needed first, staging equipment ahead of time, and staying late to get the critical equipment in, the team kept a week of delays from pushing back the grand opening. This install week was also one of the reasons the team changed its process afterward. It moved to sending Bills of Materials to the staging vendor six months in advance instead of two weeks, and switched to a different equipment staging vendor.
